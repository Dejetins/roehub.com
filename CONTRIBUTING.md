# Участие в разработке Roehub

Спасибо за желание улучшить Roehub. Нам полезны небольшие, проверяемые изменения
с понятной причиной и доказательствами результата.

## Перед изменением

1. Прочитайте `AGENTS.md` и `.codex/AGENTS.md`.
2. Для значительного изменения поведения сначала создайте issue с границей
   задачи, совместимостью и планом проверки.
3. Не включайте секреты, tokens, cookies, персональные данные, рабочие дампы или
   необработанные ответы внешних провайдеров.
4. Не добавляйте зависимости и сетевые вызовы без обоснования и проверки
   лицензии.

## Pull request

- Сохраняйте изменение узким и следуйте существующим границам модулей.
- Опишите затронутые API, DTO, хранение, конфигурацию, идентичность, внешние
  эффекты и совместимость как `none`, `compatible-change`, `breaking-change`
  или `unknown`.
- Добавьте или обновите тесты и ближайшее доказательство реальной границы,
  когда меняются API, база, браузер, контейнеры или операции.
- Укажите выполненные команды и отдельно перечислите непроверенные области.
- Не публикуйте пакеты, образы, теги или выпуски из pull request.

Обычные проверки Python-пути начинаются с узких целей:

```bash
uv run ruff check <target>
uv run pyright
uv run pytest -q <target>
```

Репозиторные wrappers и более строгие gates имеют приоритет.

## Лицензия вкладов

Если явно не указано обратное, намеренно отправленный для включения вклад
предоставляется на условиях Apache License, Version 2.0, как описано в разделе
5 файла `LICENSE`. Отправляйте только материалы, которые вы вправе предоставить
на этих условиях, и сохраняйте требуемые сторонние атрибуции.

Сообщения об уязвимостях направляйте по `SECURITY.md`, а не через обычный pull
request.
