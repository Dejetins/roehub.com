# Roehub.com — учётные записи, выпуски и измерение аудитории v1

Спецификация фиксирует открытую модель распространения Roehub с отдельной учётной записью публичного сайта, измеряемым каналом загрузок и добровольной связью самостоятельно развёрнутых установок.

## Статус

- Статус: `accepted target product specification`.
- `roehub.com` отделён от локальной платформы, имеет
  телефонную версию, документацию, выпуски, загрузки и будущую демонстрацию.
- Для выдачи ссылки на выпуск через сайт требуется вход; GitHub остаётся
  публичным альтернативным каналом открытого проекта.
- Первая версия входа использует GitHub, Google и ссылку по электронной почте.
- Добровольная связь установки не входит в первую версию и требует отдельной
  будущей задачи.
- Документ не разрешает реализацию, сбор персональных данных, публикацию
  выпуска или включение телеметрии.

## Цель

Совместить четыре результата:

1. сохранить Roehub честным открытым проектом под Apache License 2.0;
2. предоставить удобный официальный сайт, документацию и проверенные файлы
   выпуска;
3. понимать число зарегистрированных посетителей и пользователей канала
   загрузки сайта;
4. получать более сильные сведения об установках только добровольно и без
   обязательной связи self-hosted платформы с `roehub.com`.

## Подтверждённое текущее состояние

- Репозиторий `Dejetins/roehub.com` публичен под Apache License 2.0.
- `pyproject.toml#project.version` и `tools/release/release-metadata.json`
  фиксируют версию `0.1.0`.
- GitHub Releases пока отсутствуют.
- `.github/workflows/publish-app-image.yml` публикует multi-arch образ в GHCR,
  но не создаёт пользовательский GitHub Release.
- Схема автономного выпуска требует `telemetry: disabled` и
  `update_checks: explicit_opt_in`.
- GitHub API возвращает `download_count` для каждого файла выпуска, но не
  предоставляет идентичность уникальных скачавших пользователей.
- GitHub Traffic показывает посетителей и полные клонирования только за
  ограниченное окно и не является реестром установок.

## Рекомендуемая модель

Название модели: **открытая поставка с измеряемым каналом сайта**.

### Открытая часть

- исходный код, лицензия, теги, примечания к выпуску и GitHub Releases публичны;
- пользователь может получить исходный код и файлы непосредственно на GitHub;
- локальная установка не требует учётной записи `roehub.com`;
- обновления и связь установки с сайтом остаются явно включаемыми;
- сайт не заявляет, что регистрация технически ограничивает распространение
  публичного открытого выпуска.

### Измеряемая часть

- сведения о выпуске и совместимости видны всем;
- кнопка получения файла на `roehub.com` требует входа;
- после входа сервер записывает событие выдачи ссылки и перенаправляет
  пользователя на канонический GitHub asset;
- пользователь может подписаться на уведомления о выпусках;
- повторные переходы считаются отдельно от числа уникальных аккаунтов;
- в будущем пользователь может добровольно связать установку со своим
  аккаунтом для обновлений, поддержки или демонстрационных возможностей.

Такой вход измеряет официальный канал сайта, но не является защитой файла и не
даёт точного числа всех пользователей Roehub.

## Учётная запись публичного сайта

### Первая версия входа

Рекомендуемые способы:

1. `GitHub`;
2. `Google` через OpenID Connect;
3. ссылка для входа по электронной почте как универсальный резервный способ.

Отдельный пароль Roehub не создаётся. Microsoft, Apple и другие провайдеры не
включаются до появления подтверждённого спроса.

### Граница идентичности

- аккаунт сайта не равен пользователю локальной установки;
- нет общей сессии, роли или автоматического доступа к установке;
- внешний идентификатор хранится как пара `provider + subject`;
- аккаунты разных провайдеров не объединяются автоматически только по
  совпавшему адресу электронной почты;
- связывание нового провайдера требует действующей сессии пользователя;
- OAuth-токены не сохраняются после входа, если они не нужны отдельной
  утверждённой функции;
- запрашивается минимальный набор полномочий для подтверждения личности.

### Минимальные данные

- внутренний `account_id`;
- `provider`, `provider_subject`;
- подтверждённый адрес электронной почты;
- отображаемое имя и изображение профиля по желанию;
- время создания и последнего входа;
- согласия на уведомления и добровольную связь установки;
- события выдачи ссылок на выпуск.

Публичная реализация обязана предоставить выход из аккаунта, отзыв провайдера,
удаление аккаунта и связанных событий в пределах применимой политики хранения.

## Выпуски и загрузки

### Канонический источник

- версия: `pyproject.toml#project.version`;
- тег и GitHub Release: `vX.Y.Z`;
- файлы, хеши, подписи, SBOM и совместимость: release manifest и assets GitHub
  Release;
- `roehub.com` читает и кэширует опубликованные сведения, но не создаёт вторую
  независимую версию выпуска.

### Публичные маршруты

- `/releases` — история выпусков;
- `/releases/{version}` — примечания, совместимость, хеши и файлы;
- `/download` — выбор актуального выпуска и платформы;
- `/docs` — публичная документация;
- `/demo` — зарезервированная будущая демонстрация;
- `/account` — профиль, входы, уведомления и история действий канала сайта.

### Измеряемый переход

`GET /download/{version}/{asset}`:

1. требует сессию сайта;
2. проверяет опубликованный release manifest и допустимый asset;
3. записывает `download_redirect_issued`;
4. возвращает `302` на канонический `browser_download_url` GitHub;
5. не считает перенаправление доказательством установки или активного
   использования.

Если в будущем сайт начнёт самостоятельно отдавать байты файла, это будет
отдельным решением с хранением, диапазонными запросами, стоимостью трафика,
подписями и новыми доказательствами.

## Метрики

Метрики не складываются в одно «число пользователей»:

| Метрика | Что доказывает | Чего не доказывает |
|---|---|---|
| `registered_accounts_total` | число созданных аккаунтов сайта | использование Roehub |
| `registered_accounts_active_30d` | вход на сайт за 30 дней | активность локальной установки |
| `unique_site_downloaders_by_release` | уникальные аккаунты, которым выдана ссылка | завершённую загрузку или установку |
| `site_download_redirects_total` | число переходов с сайта к файлу | уникальных людей |
| `github_asset_download_count` | совокупное число загрузок конкретного asset | уникальных пользователей |
| `github_unique_cloners_14d` | уникальные клонировавшие за окно GitHub Traffic | долгосрочные установки |
| `opt_in_installations_active_30d` | добровольно активные идентификаторы установок | все установки Roehub |

В пользовательских отчётах обязательно подписывается область измерения:
«аккаунты сайта», «канал загрузок сайта», «GitHub» или «добровольно связанные
установки».

## Добровольная связь установки

Возможная будущая функция, не входящая в первую версию сайта:

- локальная установка создаёт случайный `installation_id`;
- владелец явно включает проверку обновлений или связывание аккаунта;
- передаются только версия, платформа, профиль установки, временной интервал и
  случайный идентификатор;
- не передаются стратегии, торговые данные, ключи, позиции, модели, логи или
  конфигурация;
- пользователь видит точный состав данных, может отключить передачу и удалить
  связь;
- исходный режим остаётся `telemetry: disabled` и
  `update_checks: explicit_opt_in`.

Обязательный вызов домой запрещён: он противоречит самостоятельной работе,
офлайн-режиму и принятой сетевой политике выпуска.

## Будущая демонстрация

Демонстрация закладывается в карту сайта, но не реализуется вместе с первой
версией публичной поверхности.

Допустимая последовательность:

1. общедоступный записанный обзор и реальные снимки;
2. интерактивный демонстрационный интерфейс на синтетических данных;
3. изолированные краткоживущие демонстрационные сеансы после входа.

Демонстрация не подключает реальные биржи, не принимает секреты, не выполняет
торговые операции и не разделяет данные между посетителями.

## Рассмотренные варианты

### Полностью закрыть загрузки регистрацией

Отклонено для публичного Apache 2.0 проекта с GitHub Releases: прямые ссылки и
исходный код всё равно остаются публичными, а регистрация создаёт ложное
ощущение контроля.

### Убрать регистрацию и считать только GitHub

Недостаточно: GitHub даёт совокупные загрузки assets и ограниченное окно
трафика, но не предоставляет устойчивую продуктовую аудиторию или канал связи.

### Обязательная телеметрия установки

Отклонено: даёт более полное измерение ценой доверия, офлайн-работы и принятой
политики self-hosted платформы.

### Рекомендованный вариант

Публичный GitHub + регистрация для удобного канала загрузок сайта + добровольная
связь установки в будущем.

## Контракты и инварианты

- открытая лицензия и публичный GitHub не ослабляются регистрацией сайта;
- аккаунт сайта отделён от локальной идентичности;
- release metadata имеет один источник версии;
- сайт не считает переход установкой;
- точное число всех пользователей не заявляется;
- телеметрия и проверка обновлений не включаются без отдельного согласия;
- операторские инструкции локальной платформы не становятся публичными по
  умолчанию.

## Риски и открытые вопросы

- Конкретная серверная библиотека, управление сессиями, защита от злоупотреблений
  и доставка ссылок по электронной почте выбираются отдельной технической
  спецификацией.
- Политика конфиденциальности, срок хранения и удаление данных требуют
  отдельной юридической и технической задачи до включения регистрации.
- GitHub Releases и канонический пользовательский release workflow ещё не
  реализованы.
