## Exit Semantics

TP/SL selected exit resolution is now centralized in
`resolve_tp_sl_selected_exit(...)` and reused by both lazy trade detail and the
TP/SL top-result funding adjustment. The resolver preserves the accepted exact
selected-cell behavior:

- `take_profit` wins only when `t_tp < stop_abs and t_tp < t_sl`;
- `stop_loss` wins when `t_sl < stop_abs and t_sl <= t_tp`;
- `same-bar` TP/SL ties therefore keep the existing stop-loss precedence;
- signal exit and `close_on_end` handling remain unchanged.

Funding windows use the required literal boundary:
`entry_time < funding_time <= exit_time`.

## Funding Metrics

Gross TP/SL metrics are preserved. Funding adds the same Stage `04` summary
metric family to TP/SL top results:

- `total_return_pct_net_of_funding`;
- `funding_return_pct`;
- `funding_pnl_quote`;
- `funding_events_count`.

Net return is calculated as gross `total_return_pct + funding_return_pct`.
Funding PnL uses the selected trade direction and entry-sized quantity:
`-direction * qty_base * mark_price * funding_rate`.

TP/SL funding ranking is explicitly bounded to an expanded candidate pool:
`max(top_n * 5, top_n + 100)`. Result metadata records
`funding_adjustment_scope=bounded_candidate_pool` and
`funding_adjustment_exact_global_ranking=false`.

If futures funding is requested but artifact funding arrays are unavailable, the
top rows keep gross-as-net metrics with `funding_included=false`,
`funding_adjustment_scope=unavailable`, and a
`funding_artifacts_unavailable` warning.
