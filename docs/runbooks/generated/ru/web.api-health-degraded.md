# Web-шлюз или API работают с деградацией

> Инструкция: `web.api-health-degraded` · ревизия `1` · критичность `high`

Отделить отказ edge, same-origin шлюза, готовности API и зависимостей без раскрытия сессий.

## Строгие предупреждения

- Не включайте трассировку, захватывающую headers, bodies или session material.
- Не перезапускайте все зависимости, если отказавшая граница неизвестна.

## Условия обязательной остановки

- Остановитесь, если проверка требует реальной пользовательской сессии или запроса с секретом.

## Симптомы

- Проверка здоровья API завершается ошибкой или возвращает деградацию зависимости.
- Web-шлюз не может обратиться к same-origin границе API.

## Предварительные условия

- Подтвердите установку, публичный маршрут и отказавшую границу здоровья.
- Используйте синтетическую неаутентифицированную проверку и не захватывайте сессии пользователей.

## Диагностика только разрешёнными возможностями

### `probe_health` · `observe.network.probe`

Выполните ограниченную синтетическую проверку публичного health и маршрутов same-origin шлюза.

Ожидаемое доказательство: Класс статуса, задержка и очищенный route id без headers или cookies.

### `inspect_readiness` · `observe.health.read`

Сопоставьте классы готовности Web, API и обязательных зависимостей.

Ожидаемое доказательство: Классы готовности с отметкой времени без значений среды или credentials.

## Разрешённые действия

### `diagnostics` · `observe.health.read`

Сохраняйте границу только для чтения, пока не определены готовность Web/API и состояние зависимостей.

Разрешение: `none`. Эффект: `read_only`.

### `restart_service` · `control.service.restart`

Перезапустите изолированный отказавший сервис после доказательства его границы.

Разрешение: `operator`. Эффект: `reversible`.

### `rollback_release` · `control.release.rollback`

Откатите выпуск, если отказ вызван проверенным изменением Web или API.

Разрешение: `installation_owner`. Эффект: `disruptive`.

## Откат

- Через действие `rollback_release`: Восстановите последний проверенный выпуск и повторите health и same-origin проверки.
  Доказательство: Публичный health, готовность Web и same-origin API стабильны.

## Необходимые доказательства

- Очищенная матрица статусов и задержек edge, Web, API и зависимостей.
- Переходы готовности затронутых сервисов с отметками времени.

Успех:

- Синтетические public и same-origin проверки стабильны в течение окна наблюдения.

Неуспех:

- Обязательная зависимость недоступна или граница отказа неоднозначна.

## Удаление чувствительных данных

Запрещённые ключи доказательств: `authorization`, `cookie`, `csrf`, `password`, `session`, `token`.

- Никогда не сохраняйте cookies, CSRF, session id или authorization headers.
- Сохраняйте шаблоны маршрутов и классы статуса, но не пользовательские URL или payload.

Связанные alerts: `ApiHealthDown`, `ApiMetricsDown`.
