# Control-agent недоступен или результат операции неизвестен

> Инструкция: `runtime.control-agent-unavailable` · ревизия `1` · критичность `critical`

Восстановить ограниченный контур управления хостом без обхода политики, повтора неоднозначного эффекта или раскрытия служебной идентичности.

## Строгие предупреждения

- Не монтируйте Docker socket в API, Web, worker или plugin и не запускайте произвольный shell как обходной путь.
- Не повторяйте unknown-эффект с новым operation id до сверки исходной операции.

## Условия обязательной остановки

- Остановитесь, если целостность журнала или сгенерированной политики нельзя доказать.
- Остановитесь перед rollback выпуска или разрушительным восстановлением состояния без явного разрешения installation owner.

## Симптомы

- Локальный управляющий сокет хоста недоступен, при этом основной API или PostgreSQL также могут быть остановлены.
- Control-agent отклоняет операции, потому что права, последовательность или целостность hash-chain журнала не подтверждены.
- Ограниченная операция перешла в состояние unknown после timeout или разрыва транспорта.

## Предварительные условия

- Подтвердите установку, сгенерированный профиль и локальный управляющий сокет без чтения значений идентичности.
- Сохраните локальный журнал операций и его lock-файл до любых действий по восстановлению сервиса.

## Диагностика только разрешёнными возможностями

### `inspect_health` · `observe.health.read`

Проверьте host-service control-agent, сокет и готовность сгенерированной topology через разрешённую границу хоста.

Ожидаемое доказательство: Классы состояния сервиса и сокета с отметкой времени, а также очищенные ожидаемое и фактическое состояния topology.

### `inspect_journal` · `observe.audit.read`

Проверьте права журнала, непрерывность sequence, целостность hash-chain и исходный operation id без чтения идентификационных данных.

Ожидаемое доказательство: Очищенный результат проверки целостности и terminal либо unknown состояние исходной операции.

### `verify_policy` · `observe.config.read`

Проверьте хеши сгенерированной политики и manifest перед восстановлением topology или rollback.

Ожидаемое доказательство: Совпадение policy, Compose, generation manifest и release digest без значений environment.

## Разрешённые действия

### `restart_control_agent` · `control.service.restart`

Перезапустите только host-service control-agent после успешной проверки журнала и сгенерированной политики.

Разрешение: `operator`. Эффект: `reversible`.

### `reconcile_original_operation` · `control.reconciliation.trigger`

Сверьте исходную unknown-операцию с фактической topology до решения о безопасности следующей операции.

Разрешение: `operator`. Эффект: `reversible`.

### `rollback_release` · `control.release.rollback`

Откатите последний проверенный выпуск только через типизированную границу control-agent.

Разрешение: `installation_owner`. Эффект: `disruptive`.

## Откат

- Через действие `rollback_release`: Восстановите последний проверенный выпуск и сохраните исходный журнал операций для последующей сверки аудита.
  Доказательство: Health control-agent, целостность журнала, хеши сгенерированной политики и ожидаемая topology успешно проверены.

## Необходимые доказательства

- Очищенные классы host-service, сокета, политики и topology с отметками времени.
- Последовательность журнала, результат hash-chain и состояние операции без credentials или command output.

Успех:

- Управляющий сокет доступен, журнал проверен, а ожидаемая topology сверена типизированным действием.

Неуспех:

- Целостность журнала, сгенерированной политики или эффект исходной операции остаются неизвестными.

## Удаление чувствительных данных

Запрещённые ключи доказательств: `authorization`, `cookie`, `credential`, `environment`, `identity`, `token`.

- Никогда не сохраняйте содержимое host identity-файлов, assertions, HMAC-входы или signatures.
- Сохраняйте только имена environment и классы состояния, но не значения environment, DSN или provider payloads.

## Владение и связи

Команда-владелец: `platform.operations`; роль эскалации: `installation_owner`.

Связанные alerts отсутствуют; это явно зафиксированный пробел мониторинга.

- Пробел мониторинга: Канонический alert управляющего сокета и целостности журнала control-agent должен быть добавлен на Stage 20 и пока отсутствует.

Исходная инструкция: `docs/runbooks/control-agent-emergency-recovery.md`.
