# Политика безопасности Roehub

## Поддерживаемые версии

До первого опубликованного выпуска исправления безопасности готовятся только
для текущей ветки `main`. После появления выпусков этот раздел должен содержать
явную таблицу поддерживаемых версий; наличие тега само по себе не означает
поддержку.

## Как сообщить об уязвимости

В репозитории пока не объявлен гарантированно доступный приватный канал. Не
публикуйте эксплуатационные детали, секреты, токены, cookies, персональные
данные или содержимое рабочей базы в issue, discussion, pull request либо логах
CI.

Если GitHub показывает кнопку **Report a vulnerability** на вкладке Security,
используйте её. Если кнопки нет, создайте минимальный публичный issue без
технических деталей: укажите затронутый компонент, предполагаемую серьёзность и
попросите владельца репозитория открыть приватный канал. До получения такого
канала не передавайте доказательство эксплуатации.

Для обычных ошибок без чувствительных деталей используйте публичный issue.
Сообщение должно содержать затронутую версию или commit, ожидаемое и фактическое
поведение и безопасные шаги воспроизведения.

## Обработка сообщения

Получение сообщения не обещает фиксированный срок исправления. Сопровождающие
подтверждают безопасный канал, оценивают влияние, определяют поддерживаемые
версии и публикуют исправление вместе с описанием риска, когда это безопасно.
До публикации исправления сведения раскрываются только участникам, которым они
нужны для устранения проблемы.
