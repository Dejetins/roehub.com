## Outcome and ownership

The three generated profiles now use PostgreSQL and Redis without an active
ClickHouse service/image/secret/exporter/bootstrap/health dependency. Embedded and
external configurations generated, bootstrapped and ran actual application services
in six disposable combinations. External host/port/database/credentials_ref/tls
remain explicit; no server-side shared registry filesystem is required.

Installation/runtime configuration, storage status and backup/capture/policy owner
contracts explicitly require their PG-only v2 forms. Old incompatible inputs fail
before mutation. Release/signature envelope formats remain unchanged; signature
verification was not weakened. Backup retains seven state owners and PostgreSQL
public + market_data state, including actual/absence indexes, generations,
revisions and verified frontier.

A shared client registry admits 16 market, 24 control and 8 admin physical connection
attempts before handshake. PostgreSQL also sets max_connections=48. Monitor and
maintenance use separate roles and counted admin connections; application roles do
not receive partition DDL. Native PG16 tools use a counted single-upstream guard.
Unknown/crashed sessions remain quarantined until enrolled operator recovery proves
the server stopped. The concrete remote Docker procedure is documented and tested.

Maintenance rotates batches of at most 64 active request projections, provisions at
most 12 missing historical months plus current/next months, and uses statement/lock
timeouts. The monitor exports connection/lock/long-transaction, WAL/checkpoint,
dead-tuple/autovacuum and reservation signals. Its metadata lookup required an
additional schema USAGE grant, found and corrected by the real runtime proof.

Owned paths and their final hashes are in [S06/owned-paths.json](S06/owned-paths.json),
relative to the initial dirty-tree baseline. This does not claim ownership of older
hunks in those files. Earlier changes were preserved. All 132 checked applied
PostgreSQL migration/manifest and S01–S05 report/receipt files remain byte-identical:
[S06/immutability-final.json](S06/immutability-final.json).

## Limits and handoff

The budget/recovery proof requires Linux, a direct PG16 endpoint whose IP:port keeps
its enrolled owner, one protected client registry, a trusted operator environment
and exclusive maintenance control. Transparent failover/proxies/same-address
reassignment are not proven. The supplied recovery adapter supports dedicated Docker
PostgreSQL; other control planes require an equivalent verified adapter. Malformed or
foreign records are rejected, not silently reclaimed. Operator resume leaves restart
policy `no` until the intended policy is restored. Native TLS uses verified remote
TLS plus a trusted plaintext loopback; additional libpq TLS options/required channel
binding are rejected. See the concrete storage lifecycle runbook.

No production delivery, live provider execution, browser behavior or performance
acceptance is inferred. S07 owns remaining legacy implementation/dependency/reference
closure. This stage does not execute it. Disposable S06 projects, PostgreSQL data/TLS
key and registry/transfer volumes were removed; build-cache images remain:
[S06/cleanup-final.log](S06/cleanup-final.log). Existing installed services were untouched.
