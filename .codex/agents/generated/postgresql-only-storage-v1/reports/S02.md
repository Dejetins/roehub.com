## Contracts and limits

| Boundary | Classification / actual behavior |
|---|---|
| Existing public control/identity tables and current runtime wiring | `none`, except additive nullable artifact-source columns; no reset/cutover |
| Migration manifest/bootstrap/status | `compatible-change` for existing installation data; new phase required for current readiness, original applied checksums preserved |
| Artifact persisted row | `compatible-change` for old writers: nullable source_generation/content_revision/funding_revision/source_contract_version additions; NULL means legacy/unverified |
| Future revision-aware artifact serializer/ingestion/readers | Planned `breaking-change` remains S03–S05; schema alone does not implement those consumers or certify parity |
| New market schema | New internal contract; float64/null/UTC/raw field mapping proved at schema boundary, transactional ingestion parity remains S03/S08 |
| External undocumented direct schema consumers | `unknown`; no external compatibility inferred from repository tests |

`instrument_generations` persists source UUID and monotonic revision slots separately
from coverage bounds; real server restart retains their values. Canonical changes must
advance revisions transactionally in S03. Funding has a separate durable revision.
Coverage/absence/frontier rows have generation FKs; mask overlap is rejected, counts
are generated. Missing or invalidated coverage is unknown, never complete.

Maintenance `ensure_partitions(date,integer)` serializes fixed-list DDL, accepts
at most 12 months (72 partitions) and creates no default partition. UTC month/year
boundaries and historical ranges are tested. Ingestion will provision bounded import
ranges before batches; no per-candle DDL is introduced here. Migration/application
roles remain separate; application cannot CREATE/DROP or execute lifecycle functions.
Provisioning rejects privileged ownership/membership and inherited maintenance access.
Future installation wiring must call this role provisioner; no current installation
role was altered. The external-style migration owner runs without superuser privileges.

Explicit maintenance `invalidate_instrument` fences expected generation, removes
that instrument's derived masks/summary/absence/frontier, allocates a fresh UUID and
marks the index unknown. Retained raw/canonical data require bounded rebuild before
ready. No real history reset occurred. This administrative per-key operation needs
an outer deadline and quiescence; it is not a bounded hot-path history query.

Artifact source columns describe the desired-source observation watermark. S05 must
write the complete tuple with desired_target, version published serialization and
compare generation plus candle/funding revision; legacy NULLs are not valid targets.
`payload_order` is reserved for S03 deterministic byte ordering, not proof that
version-aware upserts already exist. Old binaries remain bootable before the switch.
