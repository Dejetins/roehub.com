inventory also bypassed builder-only working-memory admission. These are fixed in
existing owners, without a scheduler, cache, adapter or numerical framework:

- `BacktestAttemptDirectory` reserves generated bytes plus 64 MiB bounded overhead
  under the existing namespace flock. Its v2 marker records total `reserved_bytes`;
  the in-memory `generated_bytes` remains the separate child/builder allowance.
  V1 markers are read conservatively with added overhead and recovered only under
  the existing exact-owner/lifetime-lock protocol. All workers sharing a root must
  upgrade/drain; old accounting cannot safely coexist with v2 writers.
- Existing full/lazy input/output IPC uses an 8 MiB per-file pre-write bound.
  Native attempts include overhead. Full IPC holds top summaries and aggregate
  telemetry, not trades; production max_top_n is 50, test profile max is 100.
  The actual assembly/serializer roundtrip of 100 rows passes below 1 MiB.
  Lazy result contains only cache status/path, independent of trade count.
  Arbitrary custom larger telemetry/top_n is not silently promised compatible.
- Prepared marker has its own 8 MiB pre-write cap. Builder admits an 8 MiB
  derivative-manifest slot before output allocation, bounds request metadata and
  checks actual serialized manifest plus NPY bytes before committing. Full/lazy
  generation estimates include sufficient manifest allowance. Generated files
  remain limited by 2 GiB; scratch by 8 GiB; free reserve by 1 GiB.
- Stdout/stderr are continuously drained through pipes with at most 1,048,576
  retained characters per stream, replacing unbounded attempt log files. Excess
  diagnostic prefix is dropped; financial result IPC is never truncated.
- Before payload attestation, native/mixed/generated preparation conservatively
  reserves eight times all declared inventory payload plus all requested output
  payload, and 1 MiB fixed working allowance. The builder receives the remaining
  configured preparation budget and retains its stricter chunk/cell bounds.
  This covers resident mmap pages and full-array validation temporaries, including
  validation of generated outputs after chunked writing. It is an allocation
  estimate, not an OS RSS ceiling for Python/JIT/allocator/scoring.
- Literal environment reads make all three disk-limit keys discoverable by the
  existing runtime inventory generator; defaults and names remain unchanged.

The simultaneous non-derivative file bound is documented in the runbook:
ownership marker (owner at most 4 MiB), creation journal (same owner plus bounded
identity), full preflight (8 MiB), full attempt or lazy input-context (8 MiB),
