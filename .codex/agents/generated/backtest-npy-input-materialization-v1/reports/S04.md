## Lifecycle, resource and timing details

- Defaults are 2 GiB generated files per attempt, 8 GiB worker reservations, and 1 GiB free-space reserve, configurable by `ROEHUB_BACKTEST_ATTEMPT_DISK_BYTES`, `ROEHUB_BACKTEST_WORKER_DISK_BYTES`, and `ROEHUB_BACKTEST_DISK_RESERVE_BYTES`. Invalid/nonpositive limits or attempt > worker are rejected. Manifest-based estimates count only missing derivatives. Existing stricter native memory/chunk/cell budgets still apply; the trusted child compute bound defaults to 512 MiB via `ROEHUB_BACKTEST_ATTEMPT_COMPUTE_BYTES`.
- Reservations are serialized by the existing worker-side admission boundary. Native reused files do not consume the generated-file allowance. The production scheduler remains single-heavy-task; no new scheduling service or proactive derivative inventory was added.
- Source lease checks use PostgreSQL `clock_timestamp()`, including revalidation after potentially blocked admission and immediately before `Popen`. Materialization, attestation and the bounded child acknowledgement wait run under the observed child timeout/cancellation path and current CPU-thread policy.
- The child inherits the attempt lifetime flock. PID, age, lease expiry, or DB epoch alone cannot authorize filesystem reclamation. An uncertain DB outcome retains durable ownership/markers; exact reap or successful locked recovery is required. Startup and periodic worker recovery check the job/materialization lease and exact recorded owner.
- A creation intent in the stable admission-lock file is fsynced, including its directory entry, before `mkdir`. Pre-marker recovery can remove only that exact recorded initialization directory with the allowed initialization files. Unrecognized/foreign directories are preserved. The final marker is atomic and durable before admission commit or child launch.
- stdout/stderr, IPC input/output and generated files belong to the same attempt directory. Success, failure, cancellation and timeout reap the child before pin/resource release and cleanup. Runtime contexts explicitly close their owned mmaps after scoring; `BacktestJobScratch.clear()` retains its existing per-call RAM-reference release role.
- Publisher journals are atomic. Dead-writer recovery reconciles pointer/manifests, handles interrupted bootstrap and cleanup, and fsyncs restored state before recovery CAS. A failed durability barrier retains quarantine for retry. Publication forces the existing builder to one process so a detached writer cannot outlive the filesystem lifetime lock.
- IPC round-trips the complete internal recipe, funding metadata/readiness and existing cost fields. `backtest-prepared-input-event/v1` carries typed prepared provenance; parent CAS persists the prepared set with `artifact-prefix-payload/v1` before acknowledging its digest. Cancellation, stale ownership, parent loss, invalid acknowledgement, and acknowledgement timeout cannot enter scoring.
- New timers distinguish `input_materialization_including_attestation`, `prepared_input_parent_acknowledgement`, `child_attempt_including_preparation_and_cleanup`, `parent_attempt_cleanup`, `parent_attempt_including_cleanup`, `parent_result_persistence`, and `worker_attempt_including_persistence`. Parent result timings reach the runner log. The previous `orchestration_elapsed_v2` definition remains the service interval through assembly, excluding final cleanup and persistence. These are timing boundaries, not a speedup claim.
