# S05 — Durable source recipes and deterministic lazy replay

Date: 2026-10-08. Executor: `codex-s05-20261008-a8136f20`.

## Outcome and scope

S05 implementation and required local proof passed. Only S05 was executed under its existing updater claim. No branch, worktree, Goal, commit, publication, deployment, credential change or existing artifact cleanup was performed. The pack updater owns acceptance and successor enablement.

Stored-recipe jobs retain the original source pin, interval, normalized financial request and runtime config identity when the worker rechecks preflight. Validation uses the saved metadata without resolving the current pointer. Unsupported math versions or inconsistent recipe/job coordinates, interval or ownership fail explicitly. Recipe-less jobs retain their established path.

The S04 creation/IPC serializers already persist optional recipes and prepared provenance. S05 reuses those seams and strengthens terminal persistence: a recipe job cannot succeed without current-attempt verified provenance; full and lazy writes require exact attempt, owner, active state and an unexpired server-clock lease. Full-job success is fenced against cancellation. Reclaim clears old provenance atomically with incrementing attempt, while preserving the frozen recipe, so a new attempt must prepare and ACK again.

Lazy replay loads the original durable proof, resolves an available physical source using bounded metadata, reserves/revalidates it under the existing ownership protocol, and verifies the entire recorded candle/mapping/funding domain before any new derivatives are accepted. Appended NPY headers/shapes and whole-file hashes may differ only after the recorded payload prefix verifies. New funding events inside the original domain are rejected, including a newly added event after the last previously recorded event but before the original end. Changed consumed payloads, missing proof and unsupported math fail explicitly.

Only selected canonical indicator rows and the selected TP/SL pair pass through the existing derivative builder, validator and mmap loader. Existing float32 risk levels are matched with the existing canonical tolerance. Replayed arrays retain original origins, lengths and source-global sentinel values, so future bars do not change original trades or final-bar behavior. Current declared derivatives are still validated against their current domains; an extended derivative is regenerated for the original replay domain instead of silently reused. Source contexts close mmaps before owned cleanup.

The versioned `research-cache/recipe-v1` key uses organization, job, selected variant, request and frozen semantic recipe. It excludes physical artifact/funding manifest location changes and operational engine/storage configuration from that recipe-key branch. Legacy `research-cache/v1` is unchanged. Physical provenance remains separate from financial identity. CSV/series use the existing cache projection, not a second financial computation pipeline.

Production lazy parent/child wiring now passes the exact reserved metadata and parent-owned attempt context. Production API candle reads also reserve a durable reader, revalidate the selected source under its transaction, and release after mmap closure; a writer is excluded during attestation. Original published-source metadata remains the result's metadata even when a newer physical snapshot supplies a proven prefix.
