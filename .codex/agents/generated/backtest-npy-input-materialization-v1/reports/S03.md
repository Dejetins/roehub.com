## Outcome and proof boundary

The implementation and required local checks passed. Native, generated and
mixed inputs use the same explicit-reference array loader and preparation core.
Real local NPY tests establish canonical row identity, exact preparation/table
equivalence, selective computation, prefix replay and negative file/path checks.
No API authorization, durable parent CAS/IPC acknowledgement, source reservation,
worker cleanup, year performance, database migration or production delivery is
claimed. Those remain the specified later-stage boundaries.

`BacktestPreparePoolsService.prepare_artifact_inputs` accepts a typed recipe,
resolved inventory, existing builder/validator and trusted attempt ownership.
It checks supported versions, effective grid/default fingerprints, canonical row
parameters, source identity and effective funding requirements before building.
Every declared derivative for the selected timeline is validated before missing
coverage is computed. Corruption, absent declared files and incompatibility fail;
they never cause a hidden recomputation. Optional signal features are validated
when present but do not force recomputation of valid signal rows.

Only missing rows and TP/SL levels go to `materialize_derived`. Its defaults hash
is recomputed for the missing indicator set after validating the full recipe.
Existing file references are retained in place. Generated files retain the
builder's real `derived_artifacts` commit marker. After completeness validation,
the loader atomically creates the distinct `prepared-inputs.yaml` job manifest
without replacing an existing marker. No synthetic slot/current metadata,
canonical-reader adapter, provider framework or alternate numerical pipeline
was introduced. No candle dataset is copied into an attempt directory.

The array port now uses `BacktestArtifactRuntimeContext`: the actual pinned
source plus explicit references, trusted roots and native metadata. The new
`BacktestSignalMatrix.row_ids` separates logical IDs from physical positions;
selection retains canonical IDs, metadata order and prefilter results. Mixed
components share the original timeline. Source reads remain read-only mmaps;
recorded consumed prefixes are mmap views rather than full candle copies.

TP/SL DTOs carry explicit timeframe, origin, end and sentinel/index domains.
`manifest_hash` remains an actual published hash or null. The separate
`input_identity_sha256` / result `hit_times_input_sha256` identifies the explicit
input set, including generated/mixed files; it is never presented as a fabricated
published manifest hash. `execute` returns `None` for risk `none` without reading
any risk file. Existing grid fraction tolerance `1e-7`, table precision, disabled
side handling and sentinel semantics remain intact. Direct risk consumers were
migrated; numerical scoring kernels were not changed.

The existing validator now exposes `attest_snapshot`, `validate_declared_files`,
`validate_source_snapshot`, `load_validated_reference` and
`validate_prepared_inputs`. Checks include pinned-root binding, path traversal,
symlink escapes, overlapping source/attempt roots, physical SHA/dtype/shape,
semantic array domains, encoding/numeric policy, mappings, sparse coverage,
coherent risk families and monotonicity. Publication-policy validation remains
separate and schema-1 parsing stays strict.

Whole-file SHA and `artifact-prefix-payload/v1` remain distinct. Actual larger
NPY headers/shapes can replay original consumed descriptors/proof after current
physical identities are validated. A consumed payload mutation fails even when
its new physical SHA is correctly declared. Prefix descriptors now admit exact
fractional UTC boundaries required by existing millisecond arrays; old descriptor
bytes and strict whole-second current-pointer timestamps are unchanged.

Scoring binding requires `acknowledged_prepared_sha256 == prepared.content_sha256`.
This canonical digest covers organization, job, owner token, attempt, recipe,
attestation and file references. It also checks the saved prepared manifest and
builder ownership marker. Another attempt's acknowledgement is rejected even
with the same recipe. S04 must obtain that acknowledgement through real parent
CAS/IPC; local calls supplying a matching digest are contract tests, not evidence
that durable acknowledgement has already been integrated.
