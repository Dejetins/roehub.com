## Outcome and proof boundary

Implementation and required local proof passed. The ledger/updater receipt owns
the acceptance transition; this report records its evidence. No publication,
deployment, credentials, branch, worktree, Goal or later stage was started.

`BacktestArtifactPrecomputeRunnerV2.materialize_derived(request,
output_directory=...)` consumes the typed snapshot embedded in the request and
produces only explicitly requested missing rows/levels. It needs no canonical
reader. The mandatory reader check now occurs at price-export entry.

Native publication and selected construction both invoke the same
`_materialize_signal_rows_v2` operation: canonical grid planning, chunk blocks,
production primary/dependency compute, signal rules/encoding and the atomic NPY
writer. Feature formulas and serialization are shared too. Sparse canonical IDs
are retained separately from compact physical positions; selected planning does
not enumerate every canonical variant key. All selected computation uses the
complete recorded source prefix, including EMA seed history. Missing-coverage
selection belongs to the S03 resolver; this builder computes exactly the missing
request it receives, without computing covered rows speculatively.

Selected TP/SL uses `materialize_hit_times_from_ohlcv_v2` and the existing writer,
preserving publisher 15m indexes, float32 level normalization and sentinel `T`.
An empty requested TP or SL family is supported explicitly; risk none bypasses
hit-time dispatch and creates no risk directory/files. No numerical formulas,
financial identities, ranking, direction or funding policy were changed.

Source file identities are bound to the verified published manifest, validated
against actual file hashes/dtypes/shapes and read-only mmap views. Actual price
timestamps constrain full and consumed domains. Supplied verified prefix proofs
are checked; pending proof is not relabeled verified. Prefix hashing now streams
bounded C-order buffers, handles endian conversion without source mutation, and
preserves NaN payload bits and the S01 digest format.

The new output directory is private and must not already exist. Closed generated
files are hashed and checked for shapes, dtypes, signal encoding, finite values,
exact risk grids, sentinel bounds and level monotonicity. The final atomic
`manifest.yaml` has `manifest_kind: derived_artifacts`, `schema_version: 1`, and
actual typed request/result mappings. It is a generated-component commit marker,
not a `job_prepared_inputs` manifest or durable worker acknowledgement. S03/S04
must complete prepared-set validation/attestation before scoring. No synthetic
slot, hash, candle-reader adapter or current-pointer operation is introduced.

Admission checks generated-file estimates and actual files plus manifest bytes,
existing cell/row budgets, candle/feature scratch and effective Numba parallel
risk scratch. Selected signal chunks execute inline in the owning job thread;
no nested thread/process pool is created. Native multiworker execution remains
available. These are conservative allocation guards with negative tests, not a
measured RSS/JIT-memory or year-performance claim.

`export_canonical_price_1m(..., output_directory=...)` additionally supports a
fresh private publication candidate with native relative paths. Existing-source
loads keep their original paths; all candidate prices, mappings, derivatives,
features, funding and root writes use the candidate root. Only private temporary
signal outputs use `r+`. Candidate success preserves every source file byte.
The legacy export call remains supported. **S04 must migrate publication callers
to candidate staging and implement reservation-owned installation/pointer
switching.** This stage does not claim that the existing legacy publication
orchestration is concurrency-safe or that a filesystem generation was installed.
