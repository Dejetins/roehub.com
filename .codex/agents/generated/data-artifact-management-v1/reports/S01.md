## D1 / D4 — catalog, profiles and immutable inputs

Keep one catalog: runtime defaults plus workstation availability, validated against the native signal-rule/compute registry. Base targets derive from `ARTIFACT_PRICE_TIMEFRAMES_V2` and `ARTIFACT_MAPPING_TIMEFRAMES_V2`; do not copy a frontend constant. No 5m/12h/1w is inferred from generic exchange support. Execution remains 1m and hit-times retain existing 15m semantics.

Proposed `ArtifactProfileV1` (strict JSON; reject unknown fields): `profile_id:UUID`, `revision:int>=1`, `catalog_revision:sha256`, `mode:on_demand|precompute`, `history:{kind:all_loaded|range,start_utc?:timestamp,end_utc?:timestamp}`, `derivative_timeframes:string[]`, `indicators:[{indicator_id,sources:string[],params:map<parameter,explicit-or-range-grid>}]`, `tp_levels_pct:number[]`, `sl_levels_pct:number[]`. All arrays unique/canonicalized; finite numeric values only. Bounds UTC half-open. Param/source values must be subsets of runtime-supported finite grids; reuse GridBuilder/native validation. Risk values must be representable on supported runtime grids; preserve sparse levels. Snapshot full effective values, rule/default/compute/precision versions and funding identity before admission, never resolve mutable defaults mid-attempt.

New profile draft: on-demand, all_loaded, all 10 derivative timeframes, every **available** supported indicator checked, all source/finite default parameter values supplied by the runtime catalog, TP/SL defaults from runtime defaults (dev 100 TP levels 0.5–50% and 50 SL levels 0.5–25%). All-selected means 40 catalog IDs here, not cross-products between indicators. A catalog addition is selected in a newly opened edit draft; save creates a new revision. An admitted profile stays immutable. Unavailable entries remain visible/disabled with reason; stale catalog revision on save returns 409 `catalog_changed` with explicit reload/rebase, not silent reinterpretation.

Empty indicators is valid: no proactive signal files. Empty TP and SL means no proactive risk files; independent nonempty TP or SL still requests that family. Empty derivative timeframes with nonempty indicators is invalid (`profile_timeframes_required`); with no indicators it is allowed and risk remains governed by the fixed hit-time contract. Omitting an indicator is not an authorization ban on later on-demand Backtests. Mode-off retains existing files. Use existing schema-2 explicit partial/empty `signals` and optional absent `hit_times`; do not insert `null` or weaken corruption checks. No new financial identity/hash scheme. Profile/control hashes are management identities separate from immutable Backtest recipes.

## D2 — persistence, demand union, source ownership

Retain modular contexts: API adapters -> artifact application/domain -> owned ports; PostgreSQL/filesystem/clock/control implementations are outbound adapters wired by apps. `market_data` owns committed source availability; `backtest_artifacts` owns desired policy, durable work and publication projections. The narrow notification is defined by the Market Data source boundary and adapted at composition, without importing artifact compute into ingestion. No broker/service fleet is needed.

Proposed additive tables (next unused migration number is selected in S02, never edit 0028):

- `backtest_artifact_installation_settings`: installation PK, control_version, capability_enabled(default false), paused, root_id/root_revision, schedule defaults, budgets, legacy_handoff state. Privileged trusted root mapping, not arbitrary client paths.
- `backtest_artifact_profiles`: `(organization_id,profile_id,revision)` immutable PK, validated profile JSON/catalog hash/creator/timestamps.
- `backtest_artifact_policies`: `(organization_id,exchange,market_type,symbol)` PK, control_version, profile FK, cadence override, anchor/local time/timezone, next_due, last_success; no base-enabled switch.
- `backtest_artifact_commands`: command UUID, non-null organization, actor ID, idempotency key, canonical body hash, command kind, original bounded response/status and created_at; unique `(organization_id,idempotency_key)`. This immutable command envelope owns atomic bulk replay and `/commands/{idempotency_key}` recovery. No separate per-item reuse of the same idempotency key.
- `backtest_artifact_requests`: request UUID, organization (nullable only for internal mandatory base/legacy), nullable command_id FK, coordinate, kind base|derivatives, trigger initial|schedule|manual|source_revision|legacy, desired source range/revision/watermark, immutable profile/root/compute identities, schedule occurrence, state/reason/build association. Command-origin requests are unique `(command_id,exchange,market_type,symbol,kind)`; FK/application checks bind child organization to command organization. Internal requests have non-null `internal_dedupe_key` in a separate unique system namespace including coordinate/kind/desired source/profile/schedule occurrence; use a partial unique index, not SQL NULL uniqueness assumptions. Automatic organization schedules have their own similarly explicit dedupe identity and do not impersonate a browser command.
- `backtest_artifact_builds`: UUID, physical coordinate, frozen source/effective-inventory/root snapshot, state, exact owner token/attempt/incarnation/epoch, checkpoints/progress/estimated reservation bytes. Existing slot ownership/readers remain authoritative for files. Partial unique coordinate reservation excludes concurrent physical builders even for incompatible demands.
- `backtest_artifact_build_requests`: `(build_id,request_id)` internal join; organization ownership checked against request, never exposed cross-tenant.
- `backtest_artifact_events`: bounded per-request sanitized history; physical logs remain privileged.
- `backtest_artifact_source_state`: coordinate PK, last_observed bounds/revision, desired target, published identity and per-timeframe readiness, last reconciliation cursor. This is a projection/checkpoint; canonical candles are authoritative.

Constraints and transactions: command envelope + policy CAS + immutable revision + all child admission requests + original response are one PostgreSQL transaction; atomic bulk validates all authorized items/capacity before commit. Duplicate same-key/same-body returns the original complete bounded command outcome (including every per-item request ID); changed body returns 409. Queue admission, reservation counters and request->build assignment lock the same coordinate/admission rows in stable order. Tenant IDs come from authorized principal scope, never request body. Request outcomes remain per organization even if one physical build satisfies many.

Compatible demand key: coordinate + root revision + exact frozen source identity/range-origin/watermark + schema/rule/default/compute/precision + funding semantics. Union sorted unique indicator/source/parameter rows, timeframes and TP/SL levels, with a common full source history including warmup. Requested derivative subranges are evaluated against the same source origin; no truncation that changes EMA. At the same source snapshot, a larger inventory can satisfy a subset. For different watermarks, create separate requests; coalesce into a newer snapshot only after proving each requested domain is contained and its source revision/prefix matches. Historical corrections cannot reuse stale prefix evidence. Incompatible identities serialize as separate builds; never write simultaneously or merge silently. A fresher shared artifact may satisfy an older request after validation; tenant response reports only its own requested/satisfied coverage and no other actor/profile/quota metadata.

Union admission reserves physical bytes once plus each organization's logical request quota. If the combined inventory exceeds configured budgets, retain each original selection, mark affected demand `resource_conflict`/`quota_exceeded`, and schedule compatible smaller groups serially where feasible. Do not silently uncheck indicators. Disabling A's policy affects A's future requests only; B's requests and existing pins survive. Shared bytes and physical build IDs are not ordinary tenant inventory. Tenant inventory projects requested coverage/own policy; privileged installation inventory may show actual aggregate usage.

## D3 — base source and short-history contract

Proposed notification `StoredCandleRangeObservedV1:{coordinate,start_utc,end_utc,observed_at,source_revision?,origin:ingest|stream|correction}` after canonical commit/visibility. ClickHouse and PostgreSQL do not share an atomic transaction: notification is a hint, not the only durable trigger. A bounded reconciler pages actual canonical stored coordinates/accepted work and queries bounds/coverage, then upserts desired source state and an initial request transactionally. Missing notifications/crash between stores are healed. WS and REST both use this seam; no synchronous artifact compute and no downloads. Compare historical extension/correction revisions as well as max timestamp; an unchanged end cannot hide a corrected prefix. Where source revision is unavailable, scheduled reconciliation revalidates consumed content before reuse; never treats min/max/count as a content digest.

Freeze finite `[first_stored_open, latest_closed_end)` per attempt. Ongoing streams cannot postpone first preparation. Target all 11 prices and 10 mappings; aggregate progress distinguishes eligible and insufficient timeframes. Proposed per-timeframe state: `waiting_for_source|queued|running|ready|insufficient_history|error`, with actual start/end, closed_bars, gaps and reason. A long timeframe with zero closed bars is `insufficient_history`, with `retry_after_source_end` set to its next aligned closed boundary; it does not enter timer retry loops. Overall ready requires all mandatory eligible files validated; if any timeframe is insufficient, report `partial` coverage with explicit per-timeframe states, not all-timeframe ready. S03 may publish a validated available-timeframe subset using existing schema-2 price/mapping lists and matching validation spec only after reader missing-timeframe behavior is tested; otherwise preserve old pointer and durable partial progress until it can. It must not fabricate zero-length arrays or silently remove a required eligible timeframe to pass validation. This conditional is a local compatibility proof gate for S03, not a user decision.

Gaps retain current rollup semantics (no fabricated candles). Coverage exposes known gaps and actual closed-bar bounds; readiness is for the requested effective domain, not an assertion of uninterrupted history. Funding is `not_applicable` for spot; required-but-unavailable funding is an explicit prerequisite failure for affected futures inputs, not a disabled/empty substitute. Historical extension may force a full rebuild when prefix origin/warmup changes. Checkpoints enable bounded output work, but incomplete staging never becomes current. ENOSPC/validation failure/unknown pointer commit preserve last-good pointer; unknown outcomes reconcile manifest/pointer under ownership before retry.

## D5 — queue, cadence and measured progress

`ArtifactScheduleV1:{interval_days:1|3|7,timezone:IANA,local_time:HH:MM,anchor_local_date:date,revision:int,next_due_at:UTC}`. Default is one calendar day; initial installation values derive explicitly from actual legacy 03:05 Europe/Moscow (not unused YAML hour), editable by installation owner. New per-instrument overrides inherit until explicitly saved. Persist local anchor on creation; manual/initial/enabling precompute do not move it. Due dates are anchor+n*interval days in local civil time. DST fold chooses first occurrence; nonexistent local time advances to first valid local minute that date. Unique schedule occurrence uses policy revision/local date; missed dates collapse to newest due watermark. Future revision edits don't mutate running snapshots. Precompute enable queues immediately if usable base exists, otherwise `waiting_for_source` with base request reference.

Proposed conservative initial limits, deliberately not capacity/performance guarantees:

| Limit | Value / rationale |
|---|---|
| Global active physical builds | 1; matches existing single publisher and avoids nested compute pools |
| Active build per coordinate | 1 regardless of organization; slot protocol still locks slot_a then slot_b |
| Signal processes / timeframe sessions | 1 / 1, preserve dev values |
| Signal memory budget / chunks | 805306368 bytes / 32–256 rows, preserve dev values |
| Total compute estimate ceiling | 5368709120 bytes from dev indicators config; admission must also honor stricter worker budget; not RSS guarantee |
| Source scan/export checkpoint | at most 20,000 1m rows (existing tail bound), one bounded chunk in flight; full history iterates checkpoints |
| Unfinished requests | 200 per organization (existing ingestion convention), 2,000 installation-wide new managed requests; coalesce same coordinate/identity before allocating |
| Bulk / list / history | 50 items; list 50 default/100 max; history 30 default/50 max; mirror current bounded workspace API |
| Reconciliation | 50 coordinates/page, one page in flight, 30-second idle tick; resumable cursor; no full reference scan |
| Events | 512/request, 30-day bounded maintenance of events only; no artifact TTL reclaim |
| Disk budget | owner-controlled; initial admission reserves staging upper bound plus 1 GiB free safety reserve. No configured capacity => `storage_unconfigured` for new work; no invented host size. Budget includes current, pins and staging; never frees them to fit. |
| Retries | classified transient I/O/DB only: 15/30/60/120/240/300 seconds, max 8 attempts per frozen request, then error. Unknown writer liveness quarantines; timer never reclaims ownership. |

A fair round-robin among organizations with FIFO within each org plus one internal-base/legacy lane prevents one organization filling every dispatch. Rotate after each completed build; base prerequisites precede only their dependents, not all other tenants. Large builds can occupy the sole slot; expose queue age, do not claim latency bounds. Admission returns explicit capacity errors and retains desired mandatory base state for reconciliation; never loses base obligation when queue is full. Bounded resources may require increasing trusted limits after future evidence, not dropping all-selected defaults.

Disposable arithmetic in `S01-catalog.json`: seven days is 10,080 minutes; four uint32 risk arrays at a deliberately conservative 150-level bound total 24,192,000 bytes, before headers/other buffers; canonical float64 OHLCV alone is 403,200 bytes. These checks only demonstrate finite sizing arithmetic, not feasibility of 40-indicator full history. Native 5-million-row/1.5-billion-cell validation ceilings remain enforced until an explicitly verified chunked extension changes them; above-bound history reports `resource_conflict` with full desired coverage intact. S03/S04 must verify bounded full-history handling, not mark truncated work ready.

`ArtifactProgressV1:{state:waiting_for_source|queued|running|retry_wait|ready|error,reason_code?,phase,timeframe?,completed_units:int>=0,total_units:int>=0|null,unit,progress_epoch,observed_at,last_checkpoint,next_retry_at?}`. Include independent base/derivative progress, source watermark and last-good publication. `operational_state:enabled|paused|unavailable|quota_blocked` is separate from task state. Plan total from frozen work; sum only homogeneous planned units; otherwise total is null. Retry starts a visible epoch; stale observations do not count down ETA. Ready means validated pointer commit, never merely generated files. Nonretryable reasons include invalid profile, unsupported coordinate, funding unavailable and resource conflict; source-dependent insufficient history waits for a new source boundary.

## D6 — API and storage authorization contracts

Proposed API prefix `/api/backtest-artifacts` (authenticated same-origin API). Strict request/response models `ArtifactInventoryPageV1`, `ArtifactDetailV1`, `ArtifactProfileV1`, `ArtifactScheduleV1`, `ArtifactProgressV1`, `ArtifactCommandResultV1`, `ArtifactStorageV1`. No raw manifest/repository serialization. UUIDs, UTC timestamps, finite enums, bounded strings (symbol <=64, cursor <=256), rejection of unknown request keys.

| Method/path | Shape and permission |
|---|---|
| GET `/defaults` | catalog revision/available IDs+sources+param specs, immutable base targets, new-policy defaults, capabilities; authenticated current research organization |
| GET `/inventory` | authorized exchange/market/search/cursor/limit -> `{snapshot_id,items,next_cursor,observed_at}`; item coordinate, own policy/version, base/derivative progress, covered_through/source_through/next_run, safe root label |
| GET `/instruments/{exchange}/{market_type}/{symbol}` | detail: own profile/runs, per-timeframe coverage/gaps, requested inventory size, last success and own sanitized failures; no aggregate foreign demand |
| PUT same path + `/profile` or `/schedule` | validated body + expected control_version + idempotency key -> new version and request outcome; organization `operations.execute` |
| POST `/build-requests` | coordinate list (1–50), action `update_now`, expected versions -> 202 `{items:[coordinate,request_id,state,outcome],control_versions}`; atomic authorization/admission; `operations.execute` |
| POST `/policies:bulk` | coordinates/expected versions plus explicit patch fields; omitted fields unchanged, no flattening mixed values; atomic batch, explicit per-item validation errors; `operations.execute` |
| GET `/requests`, `/requests/{id}`, `/requests/{id}/events` | only own organization, cursor bounds above; request IDs from other organizations return non-disclosing 404 |
| GET `/commands/{idempotency_key}` | own organization lookup to reconcile lost submit response; read only, no automatic replay |
| GET `/storage` | ordinary safe label and availability only; no server path, host capacity or cross-tenant byte totals |

Every query resolves current organization membership and authorized source coordinate server-side; management read uses `organization.read`, commands `operations.execute` (owner/admin/operator). This is stricter than current generic authenticated market-data work submission and does not widen it. New policies do not change existing research permissions. State changes enforce same-origin CSRF, nonempty idempotency key using existing admin syntax (8–128 ASCII allowed characters), body-hash dedupe and optimistic control_version; 409 stale version, 422 validation, 403 permission, 429 quota with Retry-After when known, 503 worker/control unavailable. No caller-selected org impersonation. Capability false is a truthful unavailable response, not an empty successful inventory.

Privileged proposed prefix `/api/v1/admin/organizations/{organization_id}/backtest-artifacts/storage`: GET inspect; POST `/validate`; PUT configure; POST `/cleanup:preview`; POST `/cleanup:confirm`. Require **both** organization operations permission and independent `require_installation_control`; mutations also recent auth (10 minutes), same-origin, idempotency and settings version. Privileged GET can show actual resolved path/space. Public storage DTO never carries privileged fields as null placeholders that later leak by caching. Query keys include subject/org/privilege/root revision; losing permission erases retained data.

Storage request selects a trusted `root_id` from installation configuration registry; it never submits an arbitrary absolute path. Existing rendered root registers as `backtest-primary`. If UI offers another location, owner first provisions an allowed candidate through trusted installation config; S06 exposes only those IDs. Validation returns root ID/revision, safe diagnostics and opaque short-lived validation token bound to actor/settings revision/root identity. Control-agent validates on the **worker mount**, using opened directory descriptors/no-follow traversal, rejecting symlinks and escapes at every component, narrow unique probe creation+fsync+unlink, free-space and access checks. Validate-before-configure is rechecked at commit, not trust in an old browser token.

Extend the existing typed control-agent boundary with a new storage capability providing inspect/validate/configure/cleanup-preview/cleanup-confirm and restricted service identity authorization. No shell fragment/path interpolation, credential minting or browser-to-host file operation. Candidate must be visible consistently to worker/API; mismatch is unavailable. First empty-root activation takes installation maintenance exclusion against admission/claims and checks artifacts, pins, active/queued work and staging. If any managed data/work exists at old root, return `relocation_required`, keep old mapping active. Same-root budget edits use CAS; shrinking below usage blocks new admission without deleting files. Actual relocation is excluded.

Cleanup preview returns opaque preview ID, root/version, observed physical identities and eligible bytes/reasons; only an installation owner can confirm. Confirmation is not authorization to delete everything: reacquire physical writer reservations in stable slot order, recheck non-current, no queued/active/quarantined readers, exact generation/manifest/root, no foreign/unknown live attempt. Any mismatch returns `preview_stale`/busy without destructive work for that target. Symlinks rejected. Current, pinned, unknown-liveness and active staging never eligible. Remove only owned eligible inactive data; log sanitized IDs/outcome/bytes, no raw paths/provider payload. A partial cleanup failure returns explicit per-target outcomes; cleanup is not advertised as atomic across files. No TTL/PID/mtime-based reclaim. This is the selected existing ownership protocol, not a new cleanup lock.
