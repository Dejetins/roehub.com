## Fixed behavior and compatibility

- Retry rechecks current membership and coordinate access for every request in the
  admission transaction; denied requests become errors. Frozen source identity is
  preserved and the worker computes only still-authorized derivative demand.
- Storage admission reads current installation settings under the installation
  lock, includes retained file usage and reservations, and retains the same outer
  transaction through the final effective reservation update. Budget reductions
  and increases govern the running worker without restart.
- Only enabling precompute from another mode admits immediate profile work.
  Subsequent edits coalesce to the future cadence. Schedule fingerprints exclude
  unrelated profile versions; changed schedules do not replay past occurrences.

These are `compatible-change` corrections to accepted authorization, budget and
cadence semantics; public DTO shapes are unchanged. Test/fixture type changes and
documentation are `none` for supported runtime consumers. Existing S04 optional
manifest sections require reader-first rollout: old strict readers have a
`breaking-change` forward-reader boundary, not newly introduced by S09. Production
configuration/provider/installed runtime compatibility is `unknown` because those
surfaces were not exercised. No activation or relocation is implied by local proof.
