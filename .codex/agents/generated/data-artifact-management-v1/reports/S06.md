## Requirements and implementation

- **R04–R08/R11:** actual FastAPI composition exposes strict bounded defaults,
  inventory/detail, profile/schedule, single/bulk commands, request/event history
  and command recovery over the S02–S05 PostgreSQL repository. Runtime catalog
  and frozen profiles remain authoritative; source snapshots are selected on the
  server. A browser cannot submit a root path, worker token, receipt or raw source.
  Omitted patch fields remain unchanged. `schedule: null` restores inheritance.
  Update now retains anchor/version; enabling precompute admits work immediately.
  Disabling precompute or changing only schedule persists policy without admitting
  a base refresh that could discard existing derivatives. Mandatory automatic base
  preparation is unaffected. Policy-only outcomes have `request_id=null`,
  `state=null`, `outcome=policy_updated`. Existing internal submit callers retain
  default admission and their pre-S06 body hashes remain replayable.
- **R09/R10:** physical base readiness, last-good source watermark, per-timeframe
  closed bars/bounds/gaps/insufficient-history retry boundary are projected from
  real source-state/cadence. Own base and derivative request outcomes remain
  separate. Progress strips worker checkpoints/receipts/identities and foreign
  demand. Base exposes only physical base/source/funding phases. A shared
  derivative build exposes generic activity with unknown units and no foreign
  timeframe; a private build exposes measured progress. No invented percentage,
  private aggregate inventory size or host capacity is returned to ordinary users.
- **R11/R13:** authorization and optimistic CAS precede writes; one transaction
  owns all bulk items and original response. Browser-body fingerprint is stable
  before defaults/source change, so same-body replay returns the original outcome;
  changed-body replay conflicts. Membership/catalog access is rechecked before
  recovery. Lists are bounded (inventory <=100, commands <=50, history/events <=50),
  bodies <=1 MiB, unknown fields rejected. Requests order newest-first by
  `(created_at,request_id)`. Revoked coordinates are omitted within bounded pages;
  an empty page may still have a continuation cursor. Foreign jobs/commands/cursors
  return non-disclosing 404. Mutations require operations role and same-origin.
- **R12/R13:** admin storage routes require operations permission **and** independent
  installation ownership, plus recent auth/origin/idempotency for mutations.
  The signed existing Unix control transport calls the real storage service; that
  service independently verifies owner/membership against PostgreSQL. Public
  storage responses contain safe label/state only; owner responses may contain
  path/free/used space. Configured installation ID is checked, without provisioning
  users or enabling capability. API/control main entrypoints actually include the
  new composition; absent adapters return sanitized 503/Retry-After.
- **R12:** trusted root registry reuses rendered artifact configuration, currently
  `backtest-primary`. No HTTP path registration. Probe traverses opened directory
  descriptors with no-follow checks and performs exclusive write/fsync/unlink.
  Tokens bind actor, settings version, root device/inode and five-minute expiry.
  Configure probes again under the same admission exclusion used by managed work.
  First empty setup leaves capability disabled/paused and handoff pending. Existing
  primary files, registered work, owners or pins prevent relocation; old root and
  files remain unchanged. Same-root budget/schedule CAS does not delete data.
- **R13:** cleanup is an explicit preview/confirm of one registered inactive slot.
  Strict existing pointer validation, active/inactive manifest hash/generation,
  root/slot identity, current pointer and every reader state are checked again.
  Actual deletion uses the existing 0028 durable coordinate writer reservation;
  current, queued/active/quarantined pins and other writers cannot be bypassed.
  Intent is durable before destructive IO. Unknown/failed cleanup retains ownership
  quarantine; same-key replay returns unknown, never a second deletion. No TTL
  reclaim, automatic relocation, automatic cleanup or implicit handoff was added.
