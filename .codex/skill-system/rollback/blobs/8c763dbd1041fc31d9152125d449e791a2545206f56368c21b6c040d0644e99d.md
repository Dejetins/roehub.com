# Topological Data Analysis

Use this skill to inspect the shape of data, not to replace business statistics, causal inference, A/B testing, uplift modeling, clustering validation, or out-of-sample backtest validation.

TDA outputs are structural diagnostics and hypothesis generators. Treat Mapper nodes, persistent features, loops, bridges, and topology-derived features as leads that require ordinary validation before any business recommendation.

## Trigger Map

Use this skill when the user asks for:

- Mapper graph, Mapper nodes, topology of a dataset, persistent homology, barcode, persistence diagram, Betti curve, persistence image, persistence landscape, or topological features;
- hidden structural segments, transition zones, bridges between groups, unstable clusters, structural anomalies, or embedding-space inspection;
- test/control structural balance or imbalance in a high-dimensional feature space;
- customer behavior topology, RFM-like shape, loyalty/status transition zones, promo/bonus response structure, or segment hints;
- backtest strategy-space topology, families of strategies, overfit zones, top-N strategy structure, or anomalous equity curves;
- time-series shape analysis with time-delay embeddings, cycles, regimes, or structural shifts.

Do not use this skill for simple aggregations, SQL-only checks, ordinary descriptive summaries, or standard classification/regression where topology is not part of the question.

## Required Workflow

1. Classify the analysis: tabular, customer, experiment, time series, embedding/feature space, backtest result space, or mixed.
2. Establish the business question, unit of analysis, source tables/files, period, and expected output.
3. Run data-quality profiling before TDA: shape, dtypes, missingness, duplicates, numeric/categorical split, constant columns, high cardinality, heavy tails, outliers, candidate ID/date/group/target columns, leakage risks, and sample-size adequacy.
4. Define the feature space explicitly:
   - exclude identifiers, hashes, phones, emails, names, document numbers, raw dates, and post-outcome leakage fields;
   - keep ID/group/date/target columns only as metadata for diagnostics;
   - normalize numeric features, preferring robust scaling for monetary and heavy-tailed behavior metrics;
   - encode only low-cardinality categorical fields by default;
   - document every removed row, excluded column, and imputation rule.
5. Build a simple interpretable baseline before TDA when the task involves segmentation, anomaly detection, ML, experiment balance, or business interpretation. Examples: PCA scatter, rule-based RFM/status table, ordinary clustering baseline, or descriptive test/control balance table.
6. Choose TDA method:
   - Mapper for interpretable structural visualization and node-level diagnostics;
   - persistent homology for H0/H1 signatures and stability of connected components or loops;
   - time-delay embedding for time-series shape, cycles, regimes, or period comparison;
   - topology-derived features only when a downstream ML validation design exists.
7. Run at least two stability checks when making a structural claim:
   - parameter sensitivity;
   - bootstrap/subsampling;
   - shuffled or label-permuted baseline;
   - train/holdout period comparison;
   - test/control balance check;
   - placebo period or out-of-sample backtest comparison.
8. Produce artifacts inside the task working folder, not in `data/`.
9. Write cautious interpretation in Russian. Use TDA findings as hypotheses and explicitly state what ordinary method should validate them next.

## Method Defaults

Mapper defaults:

- lens: PCA 1D/2D as the baseline; UMAP only when nonlinear structure is plausible and the environment supports it; t-SNE only as a visual cross-check;
- cover: start with `n_cubes=10`, `perc_overlap=0.3`; sensitivity grid should include nearby values;
- clusterer: DBSCAN as default, AgglomerativeClustering as a stable baseline, HDBSCAN only if installed and useful for noisy data;
- node summaries: row count, key business metrics, group shares, metadata distributions, top categorical labels, and interpretation hints.

Persistent homology defaults:

- compute H0 and H1 first; H2 only for small data and only when it is meaningful;
- avoid full pairwise distance matrices on large data unless the size is explicitly safe;
- sample or use landmarks for large inputs;
- save persistence diagram, barcode plot, and a summary table with lifetime statistics.

Time-series defaults:

- sort by time, handle missing periods, and define the time grain before embedding;
- create windows with explicit `window_size`, `delay`, and `stride`;
- compare time periods or groups only after aligning period definitions and normalizing windows where needed.

For detailed configuration and report templates, read `references/tda-workflow.md`.

## Interpretation Guardrails

Разрешенные формулировки:

- "структура данных указывает на возможную зону для проверки";
- "Mapper-граф выделяет группу, которую нужно проверить обычными метриками";
- "персистентная гомология (`persistent homology`) показывает устойчивую/неустойчивую H1-структуру при этих параметрах";
- "это гипотеза для проверки uplift, holdout-проверки или out-of-sample проверки, а не готовый бизнес-вывод".

Запрещенные формулировки без отдельного доказательства подходящим методом:

- "TDA доказала эффект";
- "эта группа гарантированно даст uplift";
- "стратегия точно не переобучена";
- "структура причинно вызвана кампанией";
- "кластер является бизнес-сегментом" без бизнес-валидации.
